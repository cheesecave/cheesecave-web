# Space 中的浏览器 ONNX 演示

[English](onnx-spaces.md)

Space 可以选择在访问者的浏览器中运行图像模型。Hub 直接用 Vue 渲染演示和编辑器，
不嵌入独立网站或 iframe。此选项不会更改 Space 的 SDK、README 卡片或 Runner 配置。

## 启用和编辑

创建 Space 时，可在原有 SDK 选项旁勾选 **Enable browser ONNX**。系统先创建仓库，
再提交 ONNX 配置。如果第二步失败，页面会保留已创建的仓库，并提供只重试启用 ONNX
的操作，不会重复创建仓库。

已有 Space 可以在 **Settings → General → Browser ONNX demo** 中启用。
**Edit demo** 打开 `/spaces/{namespace}/{name}/onnx-editor/{revision}`。编辑器占满
Hub 主布局可用的宽度和高度，并跟随主界面主题。编辑需要写权限：个人仓库所有者，
或组织的 member、admin、super-admin。外部回退来源的仓库不能在此编辑。

启用后，共用的 **App** 页签显示已保存的浏览器演示。已启用但尚未保存演示时，显示
待配置提示。关闭后恢复原有 App 内容，同时保留已保存的演示配置。

## 选择仓库文件

通过 Space 原有文件管理上传 ONNX 模型，以及需要的标签文件、示例图片。编辑器从
当前仓库和版本中选择文件。示例图片是可选的，访问者也可以选择自己的本地图片。

选择模型后，系统读取文件的实际字节数、SHA-256、输入输出名称、类型和形状；这些
信息直接展示，不要求作者填写。固定尺寸及可唯一确定的布局自动填入；动态尺寸或
存在歧义的布局需要作者选择。模型有多个输出时，需要选择要解析的输出。标签可以
从选中的 JSON 文件读取；编辑器也会尝试读取模型同目录中唯一的 `labels.json` 或
`meta.json`。

张量信息不能描述完整的模型使用方法。作者仍需根据模型要求选择任务、RGB/BGR、
缩放插值、scale、mean/std、标签和分数转换方式。模型内部已经计算 softmax 时，
额外的分数转换应选 **none**。根据任务配置生成界面后，会得到对应的图片输入、
控制项和结果组件，之后可以在画布上调整，不需要编写 JSON。

## 支持的执行范围

当前流程接收一个四维 `float32` 图像输入，批量大小为 1，支持 NCHW 或 NHWC。
图片会直接缩放到指定尺寸，支持双线性或双三次插值，以及通道缩放和归一化。
选中的 `float32` 输出可以解析为 YOLO 风格的检测框或图像分类分数。多输入模型、
不支持的张量类型、需要独立外部张量数据文件的模型会被拒绝。这是受控的图像推理
流程，不提供任意 ONNX 前处理或应用代码执行。

推理通过 Web Worker 内的 ONNX Runtime Web 执行。**自动选择**优先尝试 WebGPU，
初始化失败后回退到 WASM。模型检查和运行均需要安全上下文，通常是 HTTPS 或
localhost，因为两种计算方式的 SHA-256 校验都使用 Web Crypto API。WebGPU 还需要
浏览器和设备支持。WASM 在未开启跨源隔离时仍可运行，此时使用一个线程；显式选择 WASM
且环境已开启跨源隔离时，最多使用四个线程。运行状态会显示实际计算方式和实测耗时。

## 仓库配置契约

可选的清单文件为 `.cheesecave/onnx-space.json`：

```json
{
  "version": 1,
  "enabled": true,
  "document": null
}
```

文件不存在表示未启用。`enabled: true` 且 `document: null` 表示已启用但尚未配置。
保存后的 `document` 是经过校验的 DemoDocument，包含界面、模型资源、图像处理流程、
参数和组件选择；文档版本与清单版本独立。关闭功能不会删除该文档。此文件独立于
`README.md` 和其中的 `sdk` 信息。

加载时会固定配置所对应的仓库提交。模型、图片和标签 URL 只能指向同一 Space，
并跟随当前查看的版本。编辑器、设置和 App 链接都会保留该版本。保存使用现有提交
API，只写入清单文件，并携带上次加载或保存得到的 `parentCommit`。若仓库已有其他
提交，会提示冲突，需要重新载入并核对后再保存。编辑器重新载入失败时保留当前草稿。

Hub 只接收允许范围内的纯数据组件配置，不恢复序列化函数、脚本、事件处理器或
任意取数规则。仓库权限和原有带身份认证的资源访问规则仍然生效。

## 本地构建依赖

FormCreate 和 FcDesigner 从 `vendor-src/` 中随仓库保存、仅支持 Element Plus 的
fork 源码构建，并使用 `workspace:*` 引用。不要替换为公开仓库中的 FormCreate 包。
`pnpm prepare:space` 构建这些源码，并准备固定版本的 ONNX Runtime Web 同源资源；
`pnpm dev` 和 `pnpm build` 会自动执行此步骤。

运行时文件和第三方许可均从本站提供，不需要外部运行时 CDN。模型权重应放在用户
自己的 Space 仓库中，不放入 Web 应用源码或生产镜像。
